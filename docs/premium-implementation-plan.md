# MediNode プレミアム 実装計画（フェーズ順）

作成日: 2026-07-29
前提: `docs/premium-brushup-ideas.md`（v2/v3）の施策を、出荷可能な小さいフェーズに分解。
各フェーズは daily-question と同じ **app_flags の段階公開（off/preview/on）** で出す。

## 最重要の現状認識: なぜプレミアムへの投稿がゼロなのか

コードを読むと、投稿の「入口」と「出口」が分断されている。

| 経路 | 実体 | 問題 |
|---|---|---|
| CQキャプチャ（CqCapture.tsx） | 浮きボタン＋モーダル。0件画面・リーダーからプリフィル付きで開ける優秀なUX | **自分の個人Notionに残すだけ**。専門医には届かない |
| プレミアムへの投稿 | 設定パネルの奥 → 外部Notionフォーム（CLINICAL_QUESTION_FORM_URL）へのリンク | 設定を開く人しか出会わない・アプリを離れる・全部手入力・送った後の音沙汰なし |

つまり「疑問が湧いた瞬間」（検索0件・読了時・ふとした時）にはキャプチャが立っているのに、
そこから**専門医に届く配管が無い**。さらに心理面のハードル
（「こんな小さなこと訊いていいのか」）を下げる仕掛けも無い。

**方針: 新しい画面を作るのではなく、既存のCqCaptureモーダルに
「⭐専門医にも訊く」という送信先を1つ足す。** 投稿は「特別な行為」から
「いつものメモのついで」になる。

## Phase 1: プレミアム投稿をアプリ内・ワンタップに ★投稿ゼロ対策の本丸

目安: 実装1週間程度／KPI: 投稿数（まず週1件を目標。コンテンツ供給が週1〜2本なので週1件で十分回る）

### 1-1. 投稿API `/api/cq/submit`（新規）
- サーバー側の作者Notionトークン（新env: `CQ_INTAKE_NOTION_TOKEN` / `CQ_INTAKE_DB_ID`）で
  受付DBにページ作成。subscription/sync/_core.ts と同じくサーバーからNotion APIを叩く流儀。
- 入力: 疑問文（必須・10〜1000字）、職種・ペンネーム（任意）、出典コンテキスト
  （CqSource: どの記事/検索語から来たか）、user_id紐付け同意フラグ（任意・Phase 3用）。
- ガード: premium-access で会員判定、rate-limit.ts 流用（例: 5件/日/ユーザー）。
- テスト: route純ロジックをvitest（premium拒否・rate limit・バリデーション・Notion payload形状）。

### 1-2. CqCaptureモーダルの拡張
- 送信先を2択に:
  - 「自分のメモに残す」（現行動作。個人Notion設定者のみ）
  - 「⭐専門医に訊く」（プレミアム会員。非会員には🔒表示→プレミアム案内へ。
    **個人Notion未設定でも訊ける**ように enabled 条件を分離——シンプルモードの
    プレミアム会員こそ訊きたい人たち）
- 両方チェックも可（自分のメモに残しつつ専門医にも送る）。
- 送信後の受領体験: 「受け付けました。解決したらアプリでお知らせします」＋
  設定の「解決したみんなの臨床疑問」への導線。
- テスト: 表示条件マトリクス（個人Notion有無 × プレミアム有無）。

### 1-3. 導線の増設（すべて既存の open(prefill) を呼ぶだけ）
- 検索0件画面: プレミアム会員にはボタン文言を**「この疑問、専門医に訊いてみる」**に
  （検索語プリフィル済み）。0件が行き止まりからプレミアムの見せ場に変わる。
- リーダー末尾: 「読んでも解決しなかったら、訊いてみる」1行リンク（source付き）。
- 設定パネルの既存「臨床疑問を投稿する」: 外部フォームへのリンクをアプリ内モーダル起動に差し替え
  （CLINICAL_QUESTION_FORM_URL は非常用に残す）。

### 1-4. 心理ハードルを下げる（コピーと社会的証明）
- モーダル内に実績表示: 「これまで◯件の疑問がナレッジになりました」（resolved-cqs のcount流用）
  ＋ 直近の解決例タイトル2件。
- コピー: 「小さな疑問ほど歓迎です。教科書で調べるほどでもないこと、こそ。」
  「匿名OK・実名は表示されません」を最初から見えるところに。
- 計測: 既存の track('cq_capture_open') に加え、premium送信のファネルイベントを追加
  （open→premium選択→送信完了）。

- 受付DBの作者用チェック **「ボード公開」（実装済み・checkbox）** → ONの分だけ返す
  ティーザーAPI（resolved-cqs の公開APIと同じ流儀。タイトル・職種・投票数のみ）。
- UI: 設定の「解決したみんなの臨床疑問」を「みんなの臨床疑問」に拡張し
  **受付中／解決済み**の2タブに。受付中には「私も気になる」ボタン。

  文言は「いま投票を受け付けている疑問」。解決済みタブを先に見せる。
- ~~解決時: 投票者全員に個別プッシュ~~ **見送り（2026-07-29の判断）**。
  コード確認の結果、`resolved_cq` はトグルだけあって送信実装がまだない
  ＝ここで送ると「解決CQのプッシュ」という新しい面をこの機能が最初に開くことになる。
  うるさくしない方が優先なので、まずは静かな一覧のまま運用して様子を見る。
  必要になったら既存トグルの下で後から足せる（面は用意済み）。
- DailyCommandCenter に「投票数順の未解決CQ」を表示（執筆キューが需要順になる）
  … **Phase 2.1として未実装**。板の運用が始まって票が付いてからで十分。

## 進め方の原則

1. **各フェーズは独立して出荷可能**。フラグ（app_flags）で preview → on。
2. **Phase 1〜3 が最優先**。「投稿ゼロ」はコンテンツループ（このサービスの心臓）が
   止まっている状態なので、検索性や日常性より先に配管を繋ぐ。
3. コールドスタートは仕組みだけでは解けない——**作者のセルフシード**（Phase 2）と
   **受領体験**（Phase 1-2）をセットで。「誰かが使っている気配」が次の投稿を生む。
4. 各フェーズのKPIを DailyCommandCenter に1行ずつ足していく（計測→介入→確認のループ）。

# Phase 1 詳細設計（練り込み版）

追記日: 2026-07-29
問い:「Notionフォームに飛ぶのが入力の手間になっているのか？」

## 答え: なっている。しかもコード上、摩擦は4つ重なっている

CqCapture.tsx を精読した結果、現状のプレミアム投稿はこうなっている。

1. **書いた文章が引き継がれない**: モーダルで疑問文を入力→自分のNotionに保存→
   その後に出る小さな1行リンク「作者に投稿できます」→外部Notionフォームが開くが、
   **いま書いた疑問文はプリフィルされず、もう一度手入力**。
2. **導線が「保存成功後の1行」だけ**: 専門医への投稿リンクは、①個人Notion設定済みの人が
   ②保存に成功した後にだけ表示される。設定パネル内のリンクと合わせても、出会う機会が極端に少ない。
3. **シンプルモードのプレミアム会員が門前払い**: 個人Notion未設定の人がCQボタンを押すと
   案内モーダルが「**この機能は対象外なので非表示にして問題ありません**」と表示。
   ——設定不要が売りのプレミアム会員（＝一番訊きたい人たち）に、疑問ボタンを消すよう勧めている。
4. **送った後の音沙汰がない**: 外部フォームはアプリと切断されており、受領表示も解決通知も無い。

結論: **アプリ内完結は「あったほうがいい」ではなく必須**。
かつ、フォーム自体を作り直すのではなく、既に良くできているCqCaptureモーダルに
「専門医に訊く」の送信先を統合するのが最短で最良。

## 設計: 1つのモーダル、2つの届け先

### 疑問文は1回だけ書く
テキストエリアは共通。書いた疑問の「届け先」をチップで選ぶ:

```
┌──────────────────────────────┐
│ 疑問を残す                        │
│ ┌──────────────────────────┐ │
│ │ 敗血症性ショックでバソプレシンは…│ │
│ └──────────────────────────┘ │
│ 届け先: [✓ 自分のメモ] [✓ ⭐専門医に訊く] │
│ （⭐選択時のみ展開）                 │
│   職種（任意）▾   ペンネーム（任意）    │
│   ☑ 解決したらお知らせを受け取る        │
│ [ 送信する ]                      │
└──────────────────────────────┘
```

### ユーザー状態別の挙動（表示条件マトリクス）

| 個人Notion | プレミアム | 挙動 |
|---|---|---|
| あり | あり | チップ2つ。入口により初期値を変える（下記） |
| あり | なし | 現行どおり自分のメモのみ。⭐チップは🔒付きで表示→タップでプレミアム紹介（設定subscription） |
| なし | あり | **⭐専門医に訊くのみで開く**（現在の「対象外です」案内を廃止。ここが今回の最大の直し） |
| なし | なし | 現行の設定ガイド＋プレミアム紹介の2択に変更 |

**入口別の初期値**: FABから→「自分のメモ」ON／検索0件から→プレミアム会員なら
「⭐専門医に訊く」もON（検索語プリフィル済み）／リーダー末尾から→両方OFFで選ばせる
（source文脈チップは現行実装をそのまま利用）。

### 送信処理
- 「自分のメモ」→ 既存 `/api/notion/create-cq`（変更なし）
- 「⭐専門医に訊く」→ 新規 `/api/cq/submit`
- 両方選択時は並列実行し、成功・失敗を個別に表示（片方失敗でもう片方を巻き込まない）。

### 受領体験（送信後画面）
- 「⭐専門医に届きました。解決したらこのアプリでお知らせします」
- 実績の社会的証明: 「これまで◯件の疑問がナレッジになりました」（resolved-cqs count）
- 直近の解決例タイトル1〜2件（タップで閲覧→「こういうのが返ってくるのか」が一目で分かる）

## API `/api/cq/submit` 仕様

- **受け皿は現行NotionフォームのDBをそのまま使う**（新DBは作らない）。
  作者のトリアージ運用（既存のNotionビュー・チェック欄）が一切変わらないことが重要。
  env: `CQ_INTAKE_NOTION_TOKEN` / `CQ_INTAKE_DB_ID`（サーバー専用・クライアント露出なし）。
- 認証: Supabaseセッション必須 → premium-access（decidePremium）で会員判定。
- 入力: question（必須・10〜1000字）／occupation（固定リストから任意選択。resolved-cqs の
  「投稿者職種」表示と整合）／penName（任意・30字）／notify（bool・ログイン済みならデフォルトON）／
  source（title/url 任意）。
- notify=true のときだけ user_id をNotionページのプロパティに保存（Phase 3 の個別通知用。
  同意なしにIDを残さない）。
- レート制限: rate-limit.ts の rateLimitAsync、`cq-submit:<user_id>` で 5件/日。
- Notionページ作成: タイトル=疑問文、プロパティ=職種/ペンネーム/通知可否/出典/受付日。
- エラーは日本語化して返す（SearchErrors の humanize と同じ流儀）。

## 段階公開と計測

- app_flags に `cq_inapp`（off/preview/on）。preview中は設定リンクだけモーダル化し、
  FAB・0件導線は on で解放（daily-question と同じ運用）。
- ファネル計測: `cq_capture_open` → `cq_premium_selected` → `cq_premium_submitted`。
  DailyCommandCenter に「今週のプレミアム投稿数」を1行追加。
- 外部Notionフォームは当面残す（アプリ外・note読者からの投稿口として活きる）。

## 決めごと（推奨値つき・変更可）

1. **受け皿DB**: 既存フォームのDBを流用（推奨）。運用変更ゼロ。
2. **通知同意**: ログイン済みはデフォルトON（推奨）。Phase 3の個別通知が最初から効く。
3. **非会員への⭐表示**: 🔒付きで見せる（推奨）。「専門医に訊ける」の存在自体が
   最強のプレミアム広告なので、隠すのはもったいない。
4. レート制限: 5件/日/人（推奨）。誠実な利用を妨げず、爆撃だけ防ぐ。
